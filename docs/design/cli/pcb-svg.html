Design IndexCLI

CLI command design

pcb-svg

Renders explicit PCB SVG layer outputs and composed views from Altium PCB documents or projects.

Usage

altium-cruncher pcb-svg board.PcbDoc --views top,bottom,layers -o output/pcb-svg
altium-cruncher pcb-svg project.PrjPcb --config pcb.svg.config

Arguments

file accepts .PcbDoc or .PrjPcb. The command uses pcb.svg.config by default, or a file passed with --config. --views filters configured view names plus layers, all, or none. --layers filters individual layer outputs without changing composed view definitions.

A1 Config

The default file is pcb.svg.config and the current additive root schema is pcb.svg.config.a1; pcb.svg.config.a0 remains accepted as its predecessor. User config files may use JSONC comments and trailing commas; checked-in contract examples remain strict JSON. Generated config comments are part of the public editing surface and follow ADR-0007: string/enum fields list accepted options in the field comment. global.canvas controls SVG viewBox normalization. The default board_outline mode fits the visual canvas to the board profile plus margin_mm; all_geometry keeps the legacy all-primitive bounds. Component metadata remains in source Altium mils and includes origin-relative fields for placement consumers. layer_outputs controls generated per-layer SVG files. views[] is explicit: each view names its output SVG pattern, durable group_id, mirror setting, per-view style overrides, assembly_hlr_mode, and a draw-ordered layers array. Layer names accept legacy PcbLayer names and, when the installed altium-monkey exposes the V7-aware layer API, V7 semantic tokens such as MECHANICAL33 and MID31. Synthetic drill/slot overlays and pad-hole masks are derived from legacy physical layers only; V7-only layers render their own primitives but do not contribute drill overlays or hole knockouts (through-hole authoring on V7-only layers is gated upstream in altium-monkey 2026.8.1). Synthetic layer names include BOARD_OUTLINE, BOARD_CUTOUTS, DRILLS, SLOTS, BEND_LINES, SURFACE_COPPER_TOP, SURFACE_COPPER_BOTTOM, ASSEMBLY_HLR_TOP, ASSEMBLY_HLR_BOTTOM, ASSEMBLY_DESIGNATORS_TOP, ASSEMBLY_DESIGNATORS_BOTTOM, PIN1_TOP, and PIN1_BOTTOM.

Draw Order

The configured layers array is the view draw order, with two enforced exceptions: HLR projection renders last, and DRILLS/SLOTS render immediately before HLR. Copper internals render tracks/arcs first, then vias, polygon/region/fill copper, pads, and finally the synthetic drill/slot groups.

Styles

Global styles live under global.styles and each view can override individual fields in any style object. Unspecified fields inherit global values, including illustration and assembly_designators styles. Copper can style traces/arcs, vias, polygon copper, SMD pads, and through-hole pads independently. Silkscreen can separately enable component graphics, component designators, and board-level graphics/text. drills and slots are separate style buckets with plated and non-plated colors.

Assembly HLR

Status: initial A0 implementation. Views opt into HLR by including ASSEMBLY_HLR_TOP or ASSEMBLY_HLR_BOTTOM. Each view chooses assembly_hlr_mode as outline, detail, bounding_box, or none; simple remains accepted as a legacy alias for outline. Component overrides can set components.<designator>.projection to the same mode names, including suppressing a part with none or forcing a pad-bounds rectangle with bounding_box. The default config includes top and bottom HLR bounding-box views. The bounding_box mode uses component-owned pad geometry and does not invoke Geometer. The outline and detail modes use Geometer STEP projection when a component has an embedded model, then fall back to component pad bounds when no STEP projection can be emitted.

Projection styling is controlled by global.styles.assembly_hlr with optional per-view overrides and per-component components.<designator>.assembly_hlr overrides. Per-component settings merge over the active view style, so individual parts can force a different color, line width, curve policy, or Geometer tolerance without changing the rest of the view. STEP projections default to Fast HLR detail with Fast mesh-shadow outlines. Fast produces polylines, including when an older config requests native arcs. Explicit projection_algorithm: exact or poly retains that backend and its legacy outline default; outline_algorithm can select fast-mesh-shadow, mesh-shadow, or hlr-close independently. Fast is always the default. Customized legacy include/edge controls under Fast are rejected with an actionable error; migrate them to Fast controls or explicitly request poly/exact. Fast candidate controls live in assembly_hlr.fast (Geometer Fast options, including include_hidden, include_boundaries, include_creases, include_silhouettes, tolerances and limits); legacy edge flags apply only to poly/exact. Supported pass-through settings include color, line_width_mm, projection_algorithm, curve_mode, samples_per_curve, round_digits, include_visible, include_outline, union_polygons, mesh_linear_deflection, mesh_angular_deflection, mesh_relative, hlr_angle_tolerance, and Geometer edge flags such as edge_v_sharp or edge_h_outline.

Virtual Assembly Layers

Status: PIN1_TOP and PIN1_BOTTOM have an initial A0 implementation. The default config includes top and bottom pin-1 inspection views over copper and board outline with outline HLR on top. Pin-1 markers use a dot for normal SMD pad 1, whole-pad highlighting for through-hole pads while preserving visible drill/slot openings, and whole-pad highlighting for BGA/LGA letter-number pads. Pin-1 selection uses a manual components.<designator>.pin1_pad override first, then pad 1, then A1, then letter-number pads sorted by smallest numeric column and smallest row label so packages without A1, such as Cricket Node U5, resolve to B1. Global pin1.exclude_designator_prefixes suppresses markers by alphabetic reference-designator prefix, such as R, C, and L; a component override with pin1_enabled=true re-enables a specific component after the global exclusion. Components with only one owned pad designator are not highlighted because they have no meaningful pin-1 distinction, and free pads are ignored because they are not component-owned. The ASSEMBLY_DESIGNATORS_TOP and ASSEMBLY_DESIGNATORS_BOTTOM layers use the ported pcb-autodoc silhouette fitter with stable per-component groups. They can be composed with HLR or illustration layers.

Component Overrides

The generated JSONC config exposes optional assembly, dnp, diodes, and components sections so users can discover the available override shape from a new file. Component overrides control HLR projection mode/style, pin-1 selection/enabling, and assembly label visibility through show_designator. Toon project variants filter DNP illustrations/labels. General DNP styling, diode line art and cathode-specific overlays remain unimplemented.

Diodes

Status: planned, not implemented as rendered diode overlays in A0. The config and generated comments can identify candidate diodes for later override work. Planned behavior: detection first checks designator prefixes such as D or LED, then case-insensitive component parameter text such as value, description, and comment for diode terms. Explicit pad names such as K or C identify the cathode; numeric 1/2 footprints use a global default mapping with per-component overrides. Two-pin diodes should draw configurable diode line art plus a cathode marker by default; three-pin and four-pin diodes should fall back to standard pin-1 marking unless overridden.

Metadata

Status: initial A0 metadata exists for SVG canvas, view, layer, and component placement fields. The included_layer_ids metadata list may contain legacy integer layer ids alongside V7 saved ids; included_layer_tokens is the durable layer identity for new consumers. Component illustration and designator groups now link to this metadata through component indices and UIDs; further project metadata remains planned. The planned richer payload should reuse the existing AltiumDesign.to_json() serialization whenever project context is available. SVG-specific metadata should layer on generated view ids, group ids, canvas transform, source-to-SVG coordinate policy, projection decisions, diode decisions, DNP state, and virtual-layer decisions instead of creating a parallel project/component/netlist schema.

Board Perimeter

Include BOARD_OUTLINE in a view to draw the outer board profile. styles.board_outline.color defaults to black; line_width_mm controls its physical width (default 0.10 mm), scaling with the board when the SVG is resized.

Board Cutouts

BOARD_CUTOUTS renders board-profile interior cutouts with configurable hatch spacing, hatch angle, hatch line width, solid or dashed outline, and outline width. styles.board_cutouts.scope selects all (default) or interior. Interior reuses Mate's containment filter to reject contours touching/crossing or outside the board boundary. This selection applies to board clipping, solder-mask film and cutout artwork for the view; retained contours keep their original line/arc geometry. Hatching uses a repeated diagonal SVG pattern, with independent hatch_color and hatch_opacity; an omitted hatch color inherits the outline color. outline_opacity controls only the outline. Set label to opt into the pcb-autodoc fitted-label behavior; the default empty string disables labels. label_color (outline color when omitted), label_opacity, label_max_font_size_mm (3.0) and label_fill_ratio (0.72) control presentation. Labels fit inside the contour using the same silhouette fitter as designators, with a separate horizontal preference: label_rotation_min_gain defaults to 0.25, so vertical text must fit more than 25% larger after the size cap. Circular and nearly square openings stay horizontal. Sizes below 0.2 mm are omitted; bottom labels remain readable. The board-preview example uses the reference assembly palette and labels.

Durable Groups

Every composed view is wrapped in a durable <g> using the configured group_id. When the target SVG already exists, the command replaces that group and preserves other user-authored SVG content in the file. It also refreshes the generated scene transform for the current mirror setting and canvas width, removing the reflection when mirroring is disabled. Other scene attributes and user-authored wrappers are preserved. Annotations inside the scene follow its reflection; annotations outside it stay in page coordinates.

Output

The command writes per-layer SVGs under the configured layer output directory, composed view SVGs at each view's output_svg pattern, and a pcb.svg.manifest.a0 sidecar manifest.

Tests

L3 verifies Hydroscope layer output, geometer-backed HLR assembly views, and the cutout fixture. Unit tests cover schema rejection, default config generation, CLI view/layer selection, style merge behavior, cutout style validation, pin-1 overlay rendering, and HLR bounding-box mode without constructing the Geometer-backed HLR renderer.

Board Substrate

BOARD_SUBSTRATE is a composable virtual layer (id 9014) for exposed PCB material. Put it before copper and surface film in the draw-order list. On boards with resolved rigid-flex regions it emits one deterministic path per region and records the substack and substrate material in SVG metadata. color=auto is the default. A valid authored Material.Color wins; flex regions otherwise use flex_color (amber #D18B28), while rigid regions use the saved CFG3D.BOARDCORECOLOR when available and then rigid_color (muted tan #B6A26B). A non-auto color remains a global override and preserves the prior single-color behavior. Per-view style fields override inherited global fields.

Scoped board cutouts, round pad holes and rotated slots are removed using their native contours. Overlapping voids subtract as a union. Via mouths follow the outer side selected by film/copper layers; a standalone substrate with no outer side includes through vias only. Existing filled/capped-via suppression is retained. Tenting belongs to the film above the substrate, and the separate drill/slot layers can still paint their configured hole colors.

Mask-only artwork such as logos and text reveals this substrate wherever there is no copper underneath, rather than revealing the page background. The substrate is separate from the page background; areas outside the board and its physical voids remain transparent in this layer. Illustration presets include it first. Existing saved configs retain their layer lists and explicit colors.

"layers": ["BOARD_SUBSTRATE", "TOP", "SOLDERMASK_FILM_TOP"],
"styles": { "board_substrate": {
  "enabled": true, "color": "auto",
  "rigid_color": "#B6A26B", "flex_color": "#D18B28"
} }

Regional Surface Copper

SURFACE_COPPER_TOP (9016) and SURFACE_COPPER_BOTTOM (9017) resolve the first copper row from the requested side independently for every valid board region. Physical copper artwork is grouped by resolved layer and clipped to the union of regions where that layer is outer copper. This allows a rigid region to show TOP while an adjacent flex region shows MID2, without leaking the rigid board's internal MID2 artwork into the surface view. Invalid or unavailable region data falls back to the nominal TOP or BOTTOM layer. Raw physical layer tokens retain their existing literal-layer meaning.

Place regional surface copper after BOARD_SUBSTRATE and before solder-mask or coverlay film. Toon and the default composed top/bottom views use these regional virtual layers; individual physical layer outputs remain unchanged.

Bend Lines

BEND_LINES is an opt-in composable virtual layer (id 9015) for rigid-flex documentation. It paints the bend records attached to each board region as flat 2D lines. It does not fold, rotate, or deform the board, artwork, holes, or components. Bottom-view presentation uses the same whole-scene mirror policy as other board annotations.

global.styles.bend_lines and per-view overrides accept enabled, color, opacity, line_width_mm, line_style (solid or dashed), dash_length_mm, dash_gap_mm, and extension_mm. Defaults are amber #D97706, 0.8 opacity, 0.15 mm width, 0.5 mm dashes, 0.3 mm gaps, and a 1 mm extension at each end. Cruncher intersects each bend axis with its owning region, then extends both ends by that absolute distance. Zero stops at the region boundary. The viewBox grows to retain positive overruns. With metadata enabled, each line retains region identity, source index, fold index, bend angle, radius, and applied extension.

The current implementation reads region-local BoardRegions/Data geometry even when the optional Board6 bend cache is absent. Cruncher temporarily converts that local frame using the source region geometry envelope; Altium Monkey issue 96 tracks a typed source transform that will replace the adapter.

"layers": ["BOARD_SUBSTRATE", "BEND_LINES"],
"styles": { "bend_lines": { "line_style": "dashed", "color": "#D97706" } }

Solder-mask and Coverlay Film

SOLDERMASK_FILM_TOP and SOLDERMASK_FILM_BOTTOM resolve the first positive-thickness surface row independently for every board region. A path is emitted only where that substack authors solder mask or typed bikini coverlay; regions whose outer row is copper or dielectric receive no invented coating. Altium Monkey's typed StackupX layer identity and the AD26 layer-stack contract distinguish coverlay from ordinary solder mask. Flex membership or a material-name substring alone never creates coverlay.

Each emitted film path is clipped to its region, board profile, mask apertures, cutouts and non-plated holes/slots, independently of clip_to_outline. Overlapping apertures and cutouts subtract as a union. Tented vias remain covered. Coverlay is backed by the same V7 top/bottom solder-layer artwork, with its distinct film type and CoverlayExpansion retained by the layer-stack model. The aperture renderer reuses existing Altium SVG pad shapes, signed saved pad/via expansions and authored mask primitives; via expansion measured from the hole edge is respected. Custom pads use their saved mask contours when available; otherwise their copper contours are expanded using the saved pad expansion. Copper regions, tracks, arcs and fills with explicit ExtendedPrimitiveInformation mask settings also contribute apertures. Unsupported rule queries or primitive references are reported and omitted rather than guessed.

global.styles.soldermask_film contains enabled, color, coverlay_color and opacity. A non-auto color globally overrides both film classes. With auto, a valid authored Material.Color wins. Solder mask then uses the side's saved CFG3D.TOPSOLDERMASKCOLOR or CFG3D.BOTSOLDERMASKCOLOR, falling back to #176B3A; coverlay uses coverlay_color, amber #D18B28 by default. Saved colors are display settings, not fabrication specifications. Opacity defaults to 1 and remains explicit; saved display opacity is not applied automatically.

"styles": {
  "soldermask_film": {
    "color": "auto", "coverlay_color": "#D18B28", "opacity": 1.0
  }
}

A complete film-only CLI config is available at examples/pcb-svg/soldermask-film.config.json. Component illustration composition remains at the development visual checkpoint while the preview CLI integration is completed.

Silkscreen Surface Clipping

global.styles.silkscreen_surface.clip_mode controls the completed physical TOPOVERLAY/BOTTOMOVERLAY group, so tracks, arcs, fills, regions, strings, component graphics and board graphics follow one policy. none is the general PCB-SVG compatibility default. board clips ink to board material and removes cutouts and physical holes while allowing ink over bare substrate and exposed pads. film intersects ink with the matching region-local solder-mask/coverlay domain; the same aperture builder used to paint film therefore removes silk over film openings, cutouts, and uncoated regions even when the film layer is not itself requested.

Film clipping respects tenting: a tented via retains film and does not create a silk opening. An unsupported aperture rule omits only that unresolved aperture, matching film rendering's fail-safe behavior. New Toon illustration presets select film; explicit PCB-SVG configs retain none unless changed.

"styles": { "silkscreen_surface": { "clip_mode": "film" } }

Drill and Slot Boundaries

drills.outline and slots.outline select unfilled hole boundaries; both default to false to preserve existing filled marks. outline_width_mm sets the boundary stroke width, defaulting to 0.10 mm. Hole positions, diameters, slot lengths and combined pad/slot rotations come from the existing Altium primitive renderer. respect_tenting=true hides plated pad/via hole marks when the rendered outer side is tented. It defaults to false for compatibility; NPTH holes remain visible, and existing filled/capped-via suppression still applies.

A view containing SOLDERMASK_FILM_TOP or SOLDERMASK_FILM_BOTTOM supplies that outer side to DRILLS/SLOTS without requiring a visible copper layer. Hole boundary marks do not themselves subtract underlying artwork; film apertures and cutouts provide transparent openings. Use BOARD_CUTOUTS with hatch=false for visible cutout boundaries. The complete examples/pcb-svg/drill-preview.config.json demonstrates these settings with thin black lines and tented vias covered.

Illustration and Assembly Previews

Partial Geometer tessellations retain usable faces and report warnings with component/model context. These meshes are illustrated and cached normally.

Unsupported or unavailable attached models and Geometer model-conversion failures warn with component/body/model identity and omit only that body. A native HLR or illustration operation failure warns and omits that component illustration. Other components and board artwork continue. Failures are cached within the render job; native service, protocol and timeout errors remain fatal. Attached models that were omitted do not become pad-based assembly projections. This behavior is shared with toon.

ILLUSTRATION_TOP (9012) and ILLUSTRATION_BOTTOM (9013) are composable virtual layers, usable in individual layer outputs or configured views. The native Geometer demo style uses source colors, toon shading, Fast mesh-shadow outlines and Fast detail lines, with matching painted surfaces fused by Geometer. Embedded STEP and authored Altium extrusions share the existing placement pipeline. Authored cylinders lower directly from their analytic radius, height, standoff and color without OCCT tessellation. Extrusions and cylinders retain their Z extents; native rendering resolves bodies within each component, while components paint in visible-side height order. For a body whose complete XY bounds are covered by one equivalent rigid-board region envelope, Cruncher derives the local board thickness and asks Geometer B0 to clip transformed geometry at the requested top or bottom surface before bounds, HLR, shading and SVG geometry are produced. A through-board body can therefore contribute independent fragments to both illustration layers. Empty opposite fragments are ordinary omissions. A body crossing an outer edge, cutout, invalid region or unlike stack envelopes keeps its authored-side compatibility rendering and is not guessed onto the opposite side; ordinary mounting-side edge overhang remains visible. This release assumes a flat rigid-board Z frame and does not fold flex regions. Models may extend the SVG viewBox beyond the board. Components without bodies add no illustration.

Composed view and layer groups include standard metadata plus inkscape:groupmode="layer", human-readable inkscape:label values and ARIA labels. Inkscape therefore presents the board stack as named layers. Illustration and assembly-designator groups retain their stable machine IDs and metadata while displaying the component designator as the editor object name.

styles.illustration accepts enabled, line_width_mm (0.025) and opacity (1). The assembly designator layers (9008/9009) reuse the illustration's outline geometry. Their fitting algorithm is ported unchanged from pcb-autodoc: fit a text rectangle within the outline, try the component axis and its perpendicular, choose the largest capped font, and prefer horizontal only for equal sizes. Electrical pads supply the convex envelope for components with no authored models. Pad eligibility matches the copper renderer, including Altium testpoint pads that need its mask-only exception. Unplated locating holes are used only when no eligible electrical pads exist; plated through-hole pads remain electrical pads. The fitter itself retains the autodoc placement and sizing rules. Components with unavailable attached models are not silently treated as model-less. Parts with neither models nor pads have no inferred label geometry. Labels follow the authored body projection side and remain readable in bottom views. The reference cutout-label collision adjustment is retained.

styles.assembly_designators accepts enabled, color (falling back to assembly.designator_color, which defaults to red #FF0000), opacity, fill_ratio (0.8) and max_font_size_mm (2.5). components.<designator>.show_designator=false suppresses a label. stroke_color (default white) and stroke_width_mm (default 0, disabled) add an outline behind the text fill. The width is the full SVG stroke width in board millimetres. Rounded joins and stroke-before-fill painting preserve the letter interiors. This styling does not change the autodoc fit, font size, or placement; view overrides inherit global settings. Physical layers render first, followed by drill/slot marks, existing HLR, then the illustration/designator layers in their listed order.

Use examples/pcb-svg/illustration-preview.config.json or assembly-illustration-preview.config.json as ready-to-run top/bottom presets. The assembly preset replaces saved silk designators with red fitted labels and adds no separate HLR layer. Both retain copper, film, board silk, cutouts, light-gray holes/slots (#D3D3D3) and a 0.25 mm black perimeter. Copper text uses the existing embedded-font/TrueType, stroke-font and barcode renderer; its visibility and color follow copper_traces.

uv run altium-cruncher pcb-svg board.PrjPcb --config examples/pcb-svg/assembly-illustration-preview.config.json -o output/preview

A renderer job caches layer stacks, stable context facts, physical/virtual SVG fragments, unique tessellations, relative component SVGs, fitted labels and completed component layers. An ordered index of resolved layer identities preselects native single-layer primitives across physical and film renderers, while pads, vias and custom renderers retain their existing selection rules. Repeated symbols use SVG defs/use; assembly and plain previews reuse matching layers. Saved silk designators and graphics are independently configurable and cached. Cache keys retain geometry, body materials, pose, viewing side, resolved text and relevant style/context. PCB records are immutable during a job; a freshly loaded document starts new board-context and layer caches. Project parameters resolve special strings. The toon command shares prepared artwork across selected variants and filters DNP illustrations/labels during composition; alternate-model substitutions remain unsupported.

Persistent tessellation and illustration caching is enabled by default, using the same versioned, bounded cache and warning behavior as toon. Complete successful component artwork can be reused before loading or transforming meshes, with placements, bounds, shared symbols and ordered diagnostics bound to exact authored recipes and render settings. Failed bodies/components still retry. --cache-dir PATH selects its directory; --no-cache disables disk reads/writes while retaining in-memory reuse. These invocation options do not alter the SVG config. The timing report adds disk-cache counters and read/write durations; silk subfragments have silk_chunk rows and a part category. Direct Python render jobs use memory only unless supplied a PcbSvgModelCache.

--workers N limits concurrent native STEP tessellation and component HLR/illustration requests (positive integer, default 4; 1 is serial). Only unique cache misses are dispatched. Clients are started lazily and reused within the command; SVG composition and warnings retain source order. Embedded STEP tessellations are deduplicated and processed in a bounded batch before body-order composition; extruded models keep their serial path. This setting does not parallelize legacy STEP assembly projection, physical layers. Timings record the configured worker limit in workers. Worker count is an invocation setting, not an SVG config field.

Direct Python PcbSvgRenderJob() calls default to serial execution. To opt into parallel clients, use with PcbSvgRenderJob(workers=4) as job: and pass that job to the renderers, or explicitly call job.finish() in a finally block. The context manager closes workers on success or failure. A completed job must not accept new rendering work.

--timings PATH writes pcb.svg.timings.a0 JSON. Rows identify board, view, side and layer, with wall duration, parent ID, failure status and cache outcome (built, hit, assembled, disabled or none). Native materialization is included in its component/HLR layer time. Mixed views use side both; their individual layers retain top/bottom attribution. Parent durations include children; exclusive_seconds subtracts measured children. SVG construction and file writing are included in job totals. Informational layer/view progress also prints timings. Timings do not change SVG metadata or the existing behavior that preserves external groups during updates.

Component Layer Metadata

With include_metadata=true, the existing SVG enrichment JSON gains virtual_component_layers, described by pcb.svg.component-layers.a0. It records layer/group IDs, component indices, designators, symbol references, body indices/kinds/colors/Z extents, painting order, and designator position/size/angle. Join component indices to the existing enrichment component table; no separate netlist is created. SVG groups expose data-layer-key, data-feature, data-component-index, data-component-uid, data-component-designator and data-side. Free bodies have a null component index.

Illustration anchor coordinates are SVG millimeters before the outer scene reflection; local bounds list min XYZ then max XYZ in board-axis millimeters. Designator centers and angles are already in displayed-view coordinates. canvas.view_box_mm records the actual SVG viewBox; scene_mirror_x and scene_mirror_width_mm describe the scene reflection. Existing source-coordinate metadata remains unchanged. Stable group IDs support programmatic selection and editing within a regenerated view.

const component = svg.querySelector('[data-feature="component-illustration"][data-component-designator="U1"]');
const layer = svg.querySelector('[data-layer-key="ILLUSTRATION_TOP"]');
layer.style.display = 'none';

For editable illustration SVG presets and optional project variants, use toon. Raster conversion is left to consumers. The shared config no longer accepts the experimental global.png block.
