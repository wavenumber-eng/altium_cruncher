CLI command design

query

Queries Altium design data and prints compact JSON to stdout for scripts and agent workflows.

Purpose

query answers targeted design questions without generating artifact files. Where design writes a full review bundle to disk, query returns the smallest JSON payload that answers one question — a project overview, a filtered component list, a net list, per-pin connectivity for one designator, or a single-sheet inspection — so scripted consumers and AI agents can load only the relevant slice of design data. The command backs the repository's altium-schematic Claude Code skill and is experimental while its JSON field shapes track the underlying altium-monkey design and netlist JSON.

Usage

altium-cruncher query summary project.PrjPcb
altium-cruncher query components --sheet Codec.SchDoc --type ic
altium-cruncher query components --value-contains 10k --full
altium-cruncher query nets --contains P5V
altium-cruncher query nets --name SDA
altium-cruncher query connections U7 --pin C9
altium-cruncher query sheet Codec.SchDoc

Arguments

Project subcommands (summary, components, nets, connections) accept an optional positional .PrjPcb path or --project; when neither is passed, exactly one .PrjPcb must exist in the current directory, otherwise the command lists candidates and exits nonzero. components filters with --designator, --sheet (full hierarchy path or bare filename), --type (classification type such as ic or resistor), and --value-contains; rows are brief summary fields unless --full is passed. nets lists all nets, narrows with --contains, or returns one net's full terminal detail with --name (case-insensitive exact match). connections takes a required positional designator and an optional --pin identifier; pin identifiers may be alphanumeric (C9) and unknown designators fail with a sample-designator hint. sheet takes one .SchDoc path and needs no project; bare sheets report library references rather than project-annotated designators.

Output

Every subcommand prints exactly one JSON document to stdout and returns exit code 0, or prints a one-line error to stderr and returns exit code 1. Payload schema ids are altium_cruncher.query.summary.a0, altium_cruncher.query.components.a0, altium_cruncher.query.nets.a0, altium_cruncher.query.net_detail.a0, altium_cruncher.query.connections.a0, and altium_cruncher.query.sheet.a0. Component, net, and terminal field shapes come from altium-monkey AltiumDesign.to_json() and netlist JSON and are experimental until promoted. The summary's power_and_ground_nets list is heuristic: named nets with POWER-typed pins plus GND/VSS name matches. Because stdout is a machine-readable payload, the command routes CLI logging handlers to stderr for its duration; --quiet/--verbose still control log verbosity.

Tests

L3_public_workflows runs every subcommand against the Hydroscope fixture project and validates payload schemas, component filtering, net terminal detail, designator connectivity rows, stdout JSON purity, and unknown-designator/net error exits.
