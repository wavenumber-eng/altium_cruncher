CLI command design

mate

Generates fixture mating-board plans and runnable MCO files from a DUT PCB selection.

Purpose

mate is the first Altium Cruncher mating-board workflow. It inspects a device-under-test PCB, writes editable JSONC configuration, resolves known fixture parts, emits Monkey Change Order operations, and can execute those operations to create a new Altium project. The Cricket Node and node-test-array assets are the reference case.

The current command remains Altium-specific. The config shape is being kept portable enough to later map to KiCad and generic PCB Cruncher workflows; the draft portable shape is documented in mate-config.html.

Usage

altium-cruncher mate init mate.jsonc --force
altium-cruncher mate inspect DUT.PrjPcb --doc board.PcbDoc
altium-cruncher mate seed DUT.PrjPcb --config mate.jsonc
altium-cruncher mate parts-cache build node-test-array.PrjPcb
altium-cruncher mate plan mate.jsonc --output-mco mate.mco.jsonc --force
altium-cruncher mate run mate.jsonc --emit-mco mate.mco.jsonc --force

Arguments

AreaContract
sourceIdentifies the DUT project or PCB document. The command extracts absolute positions, source layers, nets, component footprints, free pads, board outline, and board origin information from source files.
outputControls generated project path, filenames, overwrite policy, schematic sheet style, board outline/origin preservation, and layer-stack template.
known_partsPoints to a known-parts manifest and cache root. The Cricket seed cache maps test points, mounting holes, and free NPTH alignment pads to fixture symbols and footprints.
placementDefines source mount side, mirroring, mirror origin, and output offset in mils. Source top/bottom mixing is rejected for normal component projections.
selectionUses reviewed source objects and projection selectors. Compact designator selectors such as TP1-27, M1-4, and explicit designator lists are accepted.
projectionsDescribe which output actions are generated for a source selection: place a mate part, draw source reference graphics, copy source outline/cutouts, emit PCB labels, and produce related artifacts.

Output

plan writes an MCO JSONC file. run executes that MCO and creates a project with schematic, PCB, copied libraries, placed mating components, arranged component designators, net labels, optional source-reference graphics, a user union named MATE_FEATURES, and requested artifacts such as PCB layer STEP outputs. Generated outputs default under output/mate.

The public example at examples/mate/cricket-node includes a runnable config scaffold, a known-parts manifest seed, expected operations, and input/output folder notes. Its generated schematic defaults to an ANSI D sheet. Mate symbols are emitted in natural designator order inside each symbol-type group, such as TP1, TP2, then TP10. Netted mate symbols are placed on a wide grid with centered-above schematic designators; each receives a wire that starts at the known-part signal pin hotspot and extends in that pin's native orientation. The net label uses the same orientation and the wire length is estimated from the label text so the wire continues underneath the full label while leaving buffer before the next schematic column. Its mate board outline defaults to a rectangle around the DUT bounds plus 500 mil on the left, top, and bottom, and 3000 mil on the right. Its source-pad reference graphics default to one expanded 10 mil outline on MECHANICAL_1, with clearance_mils measured from the source pad edge to the inside edge of that outline and optional multiple outlines controlled by the projection config. Outlines use the source pad's effective layer body for circular, obround, rectangular/square, octagonal/chamfered, and rounded-rectangle pads; custom and filled-pad reference graphics remain deferred. Source board cutouts can be projected as Mechanical 1 outline graphics, actual output board-cutout regions, or both; the cricket example enables both. Generated schematic components receive stable IDs, and generated PCB components carry matching SOURCEUNIQUEID, source-library, source-reference, hierarchy, description, and channel-offset metadata so Altium can bind each schematic symbol to its PCB footprint after generation. Its PCB net labels are arranged in right-side board-edge columns, one column per projection/input type, with a silkscreen header and a common computed box width; labels and headers are intentionally emitted after MATE_FEATURES so they remain loose and easy to move manually. Generated component designators default to Arial TrueType, 40 mil, bold, above each mate component. Its bottom-layer STEP artifact keeps local Z=0 at the copper mid-plane by setting STEP z_mm to -0.0175 for 0.035 mm copper, inserts the 3D body at 8.5 mm in the output PcbDoc, colors TP highlights red, and explicitly declares track and polygon STEP feature settings. User-local Altium project files are intentionally not committed.

Tests

Coverage lives in tests/test_mate.py. It verifies template generation, source inspection, selector seeding, known-parts cache metadata, config planning, CLI plan/run behavior, generated MCO shape, Sch/PCB source-link metadata, labels, part role mappings, source-reference graphics, and STEP artifact operation generation.
