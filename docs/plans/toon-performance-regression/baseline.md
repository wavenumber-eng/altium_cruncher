# Initial RT Super C1 performance baseline

Status: triage baseline complete; owner-reported 10x case still required

## Controlled input

- board: `tests/assets/projects/rt_super_c1/input/RT_SUPER_C1.PrjPcb`;
- config: unmodified config generated by Cruncher 2026.9.18;
- config SHA-256:
  `E2282C385990BBCD13F3A6E5716D836C93B20F5A8A14B1119E8E157A1DC51911`;
- views: default top and bottom;
- variants: base project population;
- workers: 4;
- persistent cache: disabled;
- repetitions: one unmeasured warm-up plus three measured runs;
- command launch: `uvx --from git+...@COMMIT acr toon ...`;
- full process wall includes the already-warmed `uvx` launcher; internal wall is
  the sum of root events in `pcb.svg.timings.a0`.

Raw outputs and timing JSON are under
`temp/toon-performance-ab/rt-super-c1` and are intentionally ignored.

## Pre-clipping versus corrected candidate

| Candidate | Cruncher | Monkey | Geometer | Full wall runs, s | Median, s | Internal median, s | SVG bytes |
| --- | --- | --- | --- | --- | ---: | ---: | ---: |
| Pre-clipping | 2026.9.18 / `79bb81e` | 2026.9.18 | 2026.9.13 | 3.459, 3.481, 3.489 | 3.481 | 1.789 | 3,766,900 |
| Corrected | 2026.9.20 / `bb76253` | 2026.9.19 | 2026.9.19 | 6.167, 6.241, 6.091 | 6.167 | 4.659 | 12,550,726 |

The corrected candidate is 1.77x slower by complete command wall, 2.60x slower
inside the render job, and emits 3.33x as many SVG bytes. Both candidates emit
exactly two SVGs.

In the representative third run, summed exclusive layer time grows from 0.723
seconds to 3.474 seconds, accounting for 2.751 seconds of the 2.870-second
internal delta. Project loading and silkscreen chunk rendering are effectively
flat. The next profiler revision must subdivide component layer rendering into
native surface, aperture, clipping, illustration and serialization work.

## 2026.9.19 attribution check

An initial comparison used 2026.9.19 / `c477f54` as the presumed old baseline.
Inspection showed that this release already contains the clipping and
surface/open-space composition algorithm, so it cannot answer the pre-clipping
question. It remains useful evidence:

| Candidate | Full wall runs, s | Median, s | Internal median, s | SVG bytes |
| --- | --- | ---: | ---: | ---: |
| Withdrawn 2026.9.19 / `c477f54` | 6.042, 6.033, 5.875 | 6.033 | 4.651 | 12,550,056 |
| Corrected branch / `bb76253` | 5.921, 5.917, 5.834 | 5.917 | 4.592 | 12,556,227 |

The corrected branch is approximately 2 percent faster in this small sample.
Its final cache/correctness remediation is therefore not the source of the RT
Super regression. The major cost is associated with the feature boundary
between 2026.9.18 and 2026.9.19.

## Limitations and next evidence

This is a triage result, not release evidence:

- only three measured repetitions were used;
- the pre-clipping release pins older Monkey and Geometer versions;
- native request count and surface/aperture contribution were not instrumented;
- RT Super does not reproduce the owner's approximately 10x case;
- browser parse/interaction time was not measured.

The next measurement must use an owner-reported slow board and exact command,
then run the full five-repetition cold/warm matrix with enhanced native branch
instrumentation.
