# Release Notes - 2026-06-14

These notes describe the 2026-06-14 public release preparation state for
`altium-cruncher` package version `2026.6.14`.

## Release Status

This patch release consumes the latest public Altium Monkey release and adds
MCO-backed blank document and project-skeleton authoring workflows.

Please report issues with the exact command, version output, expected behavior,
actual behavior, and a public-safe reproduction fixture when possible.

## Highlights

- The package consumes pinned `altium-monkey==2026.6.14`.
- The package continues to consume pinned `wn-geometer==2026.6.10`.
- The Altium Monkey dependency includes first-class mechanical layer-kind
  read/write support used by generated PcbDoc and project skeleton outputs.
- `schdoc create` writes a blank schematic document and defaults new sheets to
  D size.
- `schlib create` writes a schematic library with one empty symbol.
- `pcbdoc create` writes a generated rigid board with optional standard
  component mechanical layer pairs and layer kinds.
- `project init`, `project create`, and `project add-sheet` provide an editable
  JSONC project-skeleton workflow backed by generated MCO operations.

## Command Overview

- `schdoc create`: writes a blank `.SchDoc`, optionally from a `.SchDot`
  template or explicit custom sheet size.
- `schlib create`: writes a `.SchLib` with one empty part/symbol.
- `pcbdoc create`: writes a `.PcbDoc` with a generated rigid copper stack,
  rectangular board outline, and optional standard mechanical layer-kind
  profile.
- `project init`: writes a commented JSONC skeleton config.
- `project create`: compiles that config to MCO operations, writes the PrjPcb,
  generated SchDoc/PcbDoc documents, project parameters, and project document
  links.
- `project add-sheet`: creates a new schematic sheet and adds it to an existing
  PrjPcb.
- `pcblib create`: remains the minimal one-footprint PcbLib creation workflow
  introduced in the previous release.

## Known Caveats

- Project and PcbDoc stack authoring in this release supports generated rigid
  stacks only. Importing `.stackup` or `.stackupx` files directly into new
  PcbDoc files is deferred to Altium Monkey layer-stack authoring work.
- PcbLib creation is intentionally minimal. It creates a library and an initial
  footprint; richer footprint-primitive authoring will be added as more MCO
  operations are promoted.
- Local Altium launch, OutJob execution, and profile cleanup still require
  Windows with Altium Designer/profile folders present. Discovery/list commands
  are safe to exercise on Linux/macOS and return empty results when no local
  Altium state exists.
