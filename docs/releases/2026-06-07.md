# Release Notes - 2026-06-07

These notes describe the 2026-06-07 public release preparation state for
`altium-cruncher` package version `2026.6.7`.

## Release Status

This release updates the public CLI around agent-oriented design review,
Altium environment diagnostics, EasyEDA import availability, and project
decomposition artifacts. Users should still treat `mco` and `mate` as
experimental workflows under active development.

Please report issues with the exact command, version output, expected behavior,
actual behavior, and a public-safe reproduction fixture when possible.

## Highlights

- `altium-cruncher`, `acr`, and `ad` console entry points are available from the
  package.
- `design`, `design-review`, and `dr` now generate an agent-facing design review
  bundle with project design/netlist JSON under `design/`, serialized SchDoc/PcbDoc JSON, structured
  notes JSONC, schematic SVGs, copper-layer PCB review SVGs, a manifest, and a
  README that explains how the artifacts relate. Schematic SVGs are written
  under `sch/`; serialized document JSON is written under `json/schdoc/` and
  `json/pcbdoc/`. PCB review SVGs use the default `pcb-svg` layer-output shape
  under `pcb/layers/`, limited to copper layers including inner copper layers,
  and intentionally omit composed assembly/HLR views for fast agent context
  generation.
- `notes` extracts Altium Note objects, schematic text frames, and free text to
  sparse structured JSONC with relative paths, position metadata, and Altium
  unique ids when present. Sheet-template and title-block owned text is
  suppressed by default; lower-level page/layout fields remain available from
  raw document JSON.
- `megamaid` now includes serialized document JSON, combined and split
  extracted SchLib/PcbLib JSON, and project notes JSONC in addition to
  libraries, BOM, PnP, netlist/design JSON, schematic images, and embedded PCB
  assets. SchLib extraction is project-wide: one combined library and one flat
  split-symbol directory across all SchDocs. BOM/PnP artifacts use the shared
  `bom` and `pnp` command normalization paths; BOM JSON is the flat raw JSON,
  not grouped JSON. Configured BOM/PnP/JLC output filenames avoid repeating the
  extension in the stem, using semantic suffixes such as `_raw`, `_grouped`,
  and `_jlc-cpl` only when they add meaning.
- `installs`, `launch`, and `profiles` expose local Altium Designer install,
  launcher, and ProgramData profile diagnostics. With no file argument,
  `launch` / `ad` auto-opens a single `.PrjPcb` in the current directory,
  lists multiple local projects for explicit selection, or launches Altium
  without a document when no project is present.
- `json-dump` batch output defaults to domain folders directly under
  `output/json-dump` such as `pcbdoc/` and `schdoc/`, with `--layout flat`
  available when a single-folder output is more convenient.
- `libraries` scans `.SchLib` and `.PcbLib` files and lists discoverable symbol
  and footprint names. Human output uses current-directory-relative paths and
  terminal color; JSON output keeps absolute paths for automation.
- `mco` now exposes a maintained `mco list` operation catalog, uses
  human-readable run output by default, and supports `--json` / `--json-output`
  for machine-readable execution reports. Generated operation objects use the
  canonical `op`, `id`, `message`, `args` field order and underscore op names
  such as `schdoc.add_component` and `pcbdoc.add_text`.
- `mate` now emits primitive project setup MCO operations instead of the old
  bundled project skeleton command. Generated plans create the project,
  schematic, board, and project document entries as separate steps, then group
  schematic mutations before PCB mutations. Simple mate component insertion no
  longer emits synthetic `channel_offset` values.
- `outjob run` executes `.OutJob` files through the public `altium-monkey`
  runner. With no arguments it auto-detects one local `.PrjPcb` and runs every
  `.OutJob` referenced by that project; explicit project and OutJob arguments
  select specific jobs. The CLI runs the project-registered OutJob path by
  default, restores the source file after temporary normalization, and auto-binds
  the single project `.PcbDoc` into embedded `DocumentPath=` tokens unless
  disabled.
- `easyeda-import` is a first-class public command dependency and no longer
  requires a separate optional extra installation.
- The package consumes pinned `altium-monkey==2026.6.7`.

## Command Overview

- `version`: prints `altium-cruncher` and controlled dependency versions.
- `design` / `design-review` / `dr`: generates a design review bundle.
- `notes`: extracts schematic notes and annotation text to JSON.
- `megamaid`: decomposes a PrjPcb into reusable libraries, JSON artifacts,
  BOM/PnP/netlist outputs, schematic images, embedded assets, and a manifest.
- `installs`: lists discovered Altium Designer `X2.exe` installs.
- `launch`: launches a selected Altium Designer install, can open a file, and
  can auto-select one local `.PrjPcb` when run inside a project directory.
- `outjob`: runs project-referenced or explicit `.OutJob` files through Altium
  Designer.
- `libraries`: lists SchLib symbol names and PcbLib footprint names.
- `mco`: lists and runs MCO JSONC operation files; JSON execution reports are
  opt-in.
- `mate`: compiles a mate config into primitive MCO operations and can run the
  generated workflow.
- `profiles`: inspects and can clean selected Altium ProgramData extension
  profile state.
- `easyeda-import`: generates Altium SchLib/PcbLib assets from EasyEDA/LCSC
  component data.

## Known Caveats

- Public behavior is still being hardened against a wider range of Altium
  projects.
- Generated SVG, STEP, BOM, PnP, and JSON outputs may have incomplete handling
  for some project constructs.
- `mco` and `mate` command contracts are experimental and may change.
- Local Altium launch, OutJob execution, and profile cleanup require Windows
  with Altium Designer/profile folders present. Discovery/list commands are
  safe to exercise on Linux/macOS and return empty results when no local Altium
  state exists.
