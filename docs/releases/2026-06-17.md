# Release Notes - 2026-06-17

These notes describe the 2026-06-17 public release for `altium-cruncher`
package version `2026.6.17`.

## Release Status

This release consumes the latest public Altium Monkey release, adds MCO-backed
blank document and project-skeleton authoring workflows, and expands the beta
`mate` workflow used for generated mating-board fixtures.

Please report issues with the exact command, version output, expected behavior,
actual behavior, and a public-safe reproduction fixture when possible.

## Highlights

- The package consumes pinned `altium-monkey==2026.6.16`.
- The package continues to consume pinned `wn-geometer==2026.6.10`.
- The Altium Monkey dependency includes first-class mechanical layer-kind
  read/write support used by generated PcbDoc and project skeleton outputs.
- The Altium Monkey dependency also includes the SchLib-to-SchDoc
  insertion-order fix, so inserted schematic library symbols preserve their
  intentional draw order when generated workflows place parts.
- `schdoc create` supports a config-first workflow: first no-target run writes
  `schdoc_create.jsonc`, then a later run creates the schematic document. Direct
  `.SchDoc` targets remain supported.
- `schlib create` writes a schematic library with one empty symbol.
- `pcbdoc create` supports a config-first workflow: first no-target run writes
  `pcbdoc_create.jsonc` with the same PCB child defaults used by `prjpcb`, then
  a later run creates the PCB document. Direct `.PcbDoc` targets remain
  supported.
- `prjpcb`, `prjpcb init`, `prjpcb create`, and `prjpcb add-sheet` provide an
  editable JSONC project-skeleton workflow backed by generated MCO operations.
  A no-target `prjpcb create` run writes a sample config on first use, then uses
  the existing config on later runs. Generated configs use the A0 schema and
  expand mechanical rows directly for editing, with top/bottom layer pairs
  grouped together.
- `mate` adds free-pad selectors, destination-pad reference outlines, source
  schematic power-port projection, board-cutout scope controls, and cleaner
  single-pin schematic placement.
- `altium-cruncher` owned public contract identifiers now use
  `altium_cruncher.*.a0`. Separately owned boundary contracts such as
  `pcb.svg.config.a0`, `pcb.svg.manifest.a0`, and
  `geometry.planar_step.request.a0` remain unchanged.

## Command Overview

- `schdoc create`: with no target, writes or consumes `schdoc_create.jsonc`;
  with a `.SchDoc` target, writes a blank schematic document directly,
  optionally from a `.SchDot` template or explicit custom sheet size.
- `schlib create`: writes a `.SchLib` with one empty part/symbol.
- `pcbdoc create`: with no target, writes or consumes `pcbdoc_create.jsonc`;
  with a `.PcbDoc` target, writes a generated rigid board directly. Generated
  config defaults match the `prjpcb` PCB child object.
- `prjpcb`: with no subcommand, prints command help.
- `prjpcb init`: writes a commented JSONC skeleton config. Bare names such as
  `test` write `test.project.jsonc` and infer project name `test`.
- `prjpcb create`: with no config target, writes or consumes
  `prjpcb_init.jsonc`; with a config target, compiles that config to MCO
  operations, writes the PrjPcb, generated SchDoc/PcbDoc documents, project
  parameters, and project document links.
- `prjpcb add-sheet`: creates a new schematic sheet and adds it to an existing
  PrjPcb.
- `pcblib create`: remains the minimal one-footprint PcbLib creation workflow
  introduced in the previous release.
- `mate`: generates improved mating-board fixtures with richer selectors and
  clearer schematic output while remaining beta.

## Known Caveats

- Project and PcbDoc stack authoring in this release supports generated rigid
  stacks only. Importing `.stackup` or `.stackupx` files directly into new
  PcbDoc files is deferred to Altium Monkey layer-stack authoring work.
- PcbLib creation is intentionally minimal. It creates a library and an initial
  footprint; richer footprint-primitive authoring will be added as more MCO
  operations are promoted.
- Local Altium launch, OutJob execution, and profile cleanup still require
  Windows with Altium Designer/profile folders present. Discovery/list commands
  are safe to exercise on Linux/macOS and return empty results when no local
  Altium state exists.
