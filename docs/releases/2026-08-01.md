# Release Notes - 2026-08-01

These notes describe the 2026-08-01 public release for `altium-cruncher` package version `2026.8.1`.

## Release Status

This release consumes the stable `altium-monkey==2026.8.1` V7 PCB layer API release and extends the downstream public CLI/config/MCO surfaces for those layer identities.

Please report issues with the exact command, version output, expected behavior, actual behavior, and a public-safe reproduction fixture when possible.

## Highlights

- The package consumes pinned `altium-monkey==2026.8.1`.
- The package continues to consume pinned `wn-geometer==2026.6.10`.
- V7 layer tokens such as `MECHANICAL17` and `MID31` resolve through `pcb-svg`, `design-review`, `pcblib clean`, `pcb-layer-step`, and MCO layer-bearing operations where the upstream writer supports them.
- `pcbdoc.add_pad` accepts float `corner_radius_percent`, and fractional corner-radius percentages survive through the altium-monkey CornerRadiusChamfer lane.
- `pcbdoc.create` with `stackupx_file` supports extended-signal stacks and surfaces StackUpX GUID-enforcement errors when ids are not GUID strings.
- SVG metadata now exposes durable `included_layer_tokens` alongside legacy integer and V7 saved ids in `included_layer_ids`.

## Known Caveats

- V7-only layers have no legacy integer layer byte. Surfaces that write legacy layer bytes reject V7-only selectors with an actionable error instead of silently dropping them.
- Synthetic drill/slot overlays and pad-hole masks derive from legacy physical layers only; V7-only layers render their own primitives but do not contribute drill overlays or hole knockouts.
- Some composed PCB SVG rendering paths still depend on private altium-monkey renderer internals pending a public upstream composed-view API.
